## Evidence and decisions

The [baseline CI run](https://github.com/julesrumeautennis-cmd/campus-food-pantry-mobile/actions/runs/43969672082) covered Java/Docker, PostgreSQL, TypeScript, platform bundles and Vercel configuration. Use the current PR's Checks tab for the new shared contract and two-session approval tests. Local regression history and prior cloud observations are in [STATUS](STATUS.md). Record local, CI, device and hosted results separately. A JavaScript bundle, configuration-schema check, signed iOS build and live deployment each need their own evidence.

The task ownership, dependency and fixture handoff pattern follows [Mission VESTA](https://github.com/nicolasrufino/nasaspaceapps/blob/f933f696314d8ffe765f0282a3cb16e3a9b7cd48/AGENTS.md). Campus Pantry keeps its existing integration branch and CI gate.

The earlier Stitch guidance and the newer Figma file describe different stages. The running mobile screens determine current behavior. Jules still needs to choose which visual changes to implement. The older architecture overview illustrates routes, while the controller, Java response mapping and actual TypeScript call sites define the current wire format. Use [CONTRACTS](CONTRACTS.md) for integration. Pending business rejections and transport errors have different effects on the UI.

PR #1 contains the application. Until it lands on main, stack contributions on its application branch. No named team assignments, paid services or production migrations are needed to start the Ready issues.
